# vault-recovery-kit-v1

Golden vectors pinning the **production** public recovery kit (ADR 0007 §6):
its exact prose, and the exact SQVB bytes that prose produces.

Generated by `pnpm recovery:vectors`. Asserted by
`tests/vault/recovery-tool.test.ts`.

## Why this file exists

`vault-contracts-v1.json` already contains a `recoveryKit` record, but it uses
synthetic digests and three short placeholder strings
(`"SQVB contract reader v1"`, …) rather than the five long sentences and two
instruction blobs a real kit carries. The result was that **no committed
artifact would have caught a copy-edit to the text a real kit contains** — and
that text is not decoration. It tells a recovering user what the kit is, that it
cannot spend, that removing a device is not revocation, and which reader can
open it.

This file closes that gap by pinning `VAULT_RECOVERY_KIT_TEXT_V1` — which now
lives in `src/domain/vault/multisig-contracts.ts` rather than beside the
coordinator, because the extension that writes kits, the standalone package that
reads them, and these vectors must all agree on it byte for byte.

Changing that text is a format change. It alters the bytes of every kit minted
afterwards, so it needs a vector regeneration, and readers must keep accepting
kits written before it.

## Structure

```
records.<mainnet|signet>
  policyId
  text                  the three literals, extracted for direct comparison
  unpublishedDigests    kit + kitHex with the all-zero digest sentinel
  publishedDigests      kit + kitHex with real non-zero digests
```

## Both digest states are pinned, on purpose

A kit minted before the first standalone release carries
`standaloneToolSourceDigest` and `standaloneToolArtifactDigest` as 32 zero
bytes. That is deliberate — inventing a digest would claim a verifiable
provider-independent exit that nobody can check — and such kits will exist for
as long as the Vaults they describe do.

So the reader must keep accepting both forms forever, and both are pinned here.
`unpublishedDigests` is not a legacy case to be removed once a release exists;
it is a permanent part of the format.

## Encoding

SQVB record type `10`, contract version `1`. Field order and the shared writer
primitives are documented in `vault-contracts-v1.md`. Each `kitHex` here is the
complete serialized record, and the test round-trips it through
`parseVaultRecoveryKit` and back through `serializeVaultRecoveryKit`, so a
reader that accepts a field it cannot reproduce fails.

## Fixture material

Derived from three published BIP39 test-vector mnemonics. Public by definition;
never fund them.
