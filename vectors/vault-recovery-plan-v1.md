# vault-recovery-plan-v1

Golden vectors for the `recovery` / `recovery-exit` plan shape — the transaction
the ADR 0007 §6 standalone recovery package produces when opening a Vault
without Drey.

Generated by `pnpm recovery:vectors` (also run as the last step of
`pnpm vectors:generate`). Asserted by `tests/vault/recovery-tool.test.ts`.

## Why this file exists

`kind: 'recovery'` with a `recovery-exit` destination has been legal in the
contract schema since B0, but before C7 it had never been serialized, PSBT
constructed, signed, combined, or finalized anywhere in this codebase. A shape
whose first execution happens during a real recovery is a shape nobody has
tested. These vectors move that first execution into CI.

## Structure

```
records.<mainnet|signet>
  policy        the full VaultPolicyIdentityV1
  kitHex        the public recovery kit these plans were built from
  sentinels     the three published standalone source sentinels
  cases.sweep       every input, one output, no change
  cases.withChange  one input, destination plus current-policy change
```

Each case carries:

| Field | Meaning |
| --- | --- |
| `utxoFile` | The untrusted UTXO input as the tool accepts it on disk |
| `plan` | The finalized `VaultUnsignedPlanV1`, including `planDigest` |
| `canonicalPlanHex` | Exact canonical SQVB plan bytes |
| `unsignedPsbtHex` | `constructVaultPsbt` output |
| `partials` | One single-role partial-signature result per role |
| `quorums` | Combined PSBT, finalized transaction, txid, wtxid, real vsize |

## The two quorums, and the one that is deliberately absent

`quorums` contains exactly `desktop-a+recovery-c` and `mobile-b+recovery-c` —
the two drills §6 requires. **A+B is deliberately not present.**

`finalizeVaultPsbt` deterministically selects A+B whenever all three signatures
are available. A vector generated by "sign with every role, then finalize" would
therefore produce a perfectly valid artifact that never exercised either
required drill, and would keep passing forever while proving nothing about A+C
or B+C. Enumerating the quorums explicitly is what makes this file evidence.

Within a case, both quorums share a **txid** and differ in **wtxid**. That is
correct and load-bearing: segwit keeps signatures in the witness, so a different
pair of signers spending the same inputs produces the same transaction id. The
test asserts both halves of that — equal txids, unequal wtxids — because equal
wtxids would mean the vector was not actually covering two distinct signature
sets.

## The standalone sentinels

Where a Drey coordinator records signed gateway evidence, the standalone tool
writes published constants:

| Field | Value |
| --- | --- |
| `source.backendInstanceIdHash` | `sha256("drey-vault-standalone-recovery-v1/no-backend")` |
| `source.classificationRevisionHash` | `sha256("drey-vault-standalone-recovery-v1/no-revision")` |
| `inputs[].classificationEvidenceHash` | `sha256("drey-vault-standalone-recovery-v1/no-classification")` |

They are distinctive strings rather than zeros so an auditor can tell an offline
plan from a gateway plan at a glance. More usefully, the classification sentinel
is not the evidence hash of any real record, so B3's `assertEvidenceInput`
refuses such a plan with `input_binding_mismatch` — a standalone plan cannot be
laundered back into the asset-safe path without finding a SHA-256 preimage. Even
if one were, `classification: 'unknown'` fails B3's classification gate with
`unsupported_classification`. It fails closed twice, for independent reasons.

The reverse direction is closed too: `vault-capability.ts` refuses any plan
whose `kind` is not `withdrawal`, so the extension coordinator cannot mint this
shape at all.

## Bitcoin Core cross-check

**Not yet performed.** `vectors/vault-psbt-v1.md` documents `decodepsbt` /
`combinepsbt` / `finalizepsbt` cross-checks against Bitcoin Core 30.x; the
equivalent has not been run for these vectors, and this file does not claim it.
Running it requires a local Bitcoin Core 30.x — deliberately not the deployed
Drey gateway's node, which would defeat the purpose of a provider-independence
artifact.

## Fixture material

Derived from three published BIP39 test-vector mnemonics. They are public by
definition and must never hold value.
